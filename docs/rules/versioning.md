# Версионность

## 1. Схема

Одна SemVer-версия на всё решение: Python, dbt, DAG и Docker деплоятся вместе.

Источник истины:

- `version` в `pyproject.toml`;
- annotated git tag `vX.Y.Z`;
- `version` в `dlh/dbt/dbt_project.yml` повторяет версию решения;
- `CHANGELOG.md` в формате Keep a Changelog.

Правила:

- `MAJOR` — ломающее изменение контракта данных, схемы или поведения.
- `MINOR` — новый домен или витрина без поломки старого.
- `PATCH` — исправления, документация, внутренний рефакторинг.
- До `1.0.0` ломающие изменения допустимы в `MINOR`.
- Схема ClickHouse версионируется отдельно: `001`, `002`, а не SemVer.

## 2. Роадмап

| Версия | Смысл | Состояние |
|---|---|---|
| `0.0.1` | Инициализация репозитория | Вошла в первый коммит |
| `0.0.2` | Базовые правила | Вошла в первый коммит |
| `0.0.3` | Правила Git | Вошла в первый коммит |
| `0.0.4` | Агентская инфраструктура | Текущее состояние |
| `0.0.5` | Comlink | Следующий блок |
| `0.0.6+` | ClickHouse, dbt, Airflow | Номера и границы уточняются |
| `0.1.0` | Готовая инфраструктура | Все сервисы поднимаются и связаны |
| `1.0.0` | Готовый продукт | Ежедневный пайплайн и витрины работают стабильно |

`0.0.1`–`0.0.4` вошли в один начальный коммит; отдельные теги для них не ставились. Текущий тег: `v0.0.4`.

## 3. Порядок релиза

1. Обновить `version` в `pyproject.toml` и `dlh/dbt/dbt_project.yml`.
2. Обновить `CHANGELOG.md`.
3. Сделать коммит `chore(release): X.Y.Z`.
4. Поставить annotated tag `vX.Y.Z`.
5. Push и push тегов выполняются только по явному запросу.

## 4. Текущее состояние

Версия `0.0.4`. Следующий блок — `0.0.5`, Comlink. До него новые инструменты не добавляются.
